# 文档维护指南

## 📌 文档管理规范

### 文档位置
- 所有 Markdown 文档必须存放在 `docs/` 目录下
- 根目录不允许保留 `.md` 文件（README.md 除外）

### 文档分类

文档按以下分类组织：

1. **设备管理功能** - 设备管理相关功能文档
2. **项目架构** - 架构设计和模块说明
3. **图像识别** - 图像识别模块文档
4. **性能优化** - 性能优化相关文档
5. **功能设计** - 功能设计方案文档
6. **开发周报** - 每周开发总结
7. **阶段报告** - 项目阶段完成报告

### 命名规范

#### 文件名格式
- 使用英文大写字母
- 单词间用下划线分隔
- 示例：`FEATURE_NAME.md`

#### 分类前缀（可选）
为便于管理，可使用分类前缀：
- `DEVICE_*` - 设备管理相关
- `IP_*` - IP 地址管理相关
- `CLUSTER_*` - 集群配置相关
- `WEEK*_*` - 周报相关
- `PHASE*_*` - 阶段报告相关

### 文档模板

```markdown
# 文档标题

## 功能概述
简要说明功能或模块的作用（1-2 句话）

## 技术实现
详细的技术实现说明，包括：
- 架构设计
- 关键代码
- 数据流程

## 使用方法
如何使用该功能，包括：
- 配置步骤
- 使用示例
- 注意事项

## 相关文档
- [相关文档 1](./RELATED_DOC1.md)
- [相关文档 2](./RELATED_DOC2.md)

## 更新日志
- 2026-03-30: 初始版本
```

## 🔄 新增文档流程

### 步骤 1: 创建文档
在 `docs/` 目录下创建新文档，遵循命名规范。

### 步骤 2: 更新索引
编辑 `docs/README.md`，在对应分类下添加文档链接。

**示例**：
```markdown
### 新功能
- [新功能说明](./NEW_FEATURE.md) - 功能简介
```

### 步骤 3: 添加分类（如需要）
如果是全新分类，需要在索引文件中添加新的分类章节。

### 步骤 4: 提交检查
确保：
- ✅ 文档在 `docs/` 目录下
- ✅ 文件名符合规范
- ✅ 索引文件已更新
- ✅ 文档链接正确

## 📋 索引更新检查清单

每次新增文档后，请检查：

- [ ] 文档已移动到 `docs/` 目录
- [ ] 文件名符合命名规范
- [ ] 在 `docs/README.md` 中添加链接
- [ ] 链接放在正确的分类下
- [ ] 添加简短的文档描述
- [ ] 检查所有链接是否有效
- [ ] 更新"最后更新时间"

## 🗑️ 文档清理

### 何时清理
- 文档内容已过时
- 功能已被移除
- 文档被新文档替代

### 清理流程
1. 确认文档可以删除
2. 从索引文件中移除链接
3. 删除文档文件
4. 提交变更

## 🔍 文档质量要求

### 内容要求
- ✅ 标题清晰明确
- ✅ 有功能概述
- ✅ 有使用示例
- ✅ 有注意事项
- ✅ 链接到相关文档

### 格式要求
- ✅ 使用 Markdown 语法
- ✅ 标题层级清晰（H1 → H2 → H3）
- ✅ 代码块使用语法高亮
- ✅ 链接使用相对路径

### 语言要求
- ✅ 技术术语使用英文（括号内中文注释）
- ✅ 语句通顺，无错别字
- ✅ 格式统一，风格一致

## 📊 文档统计

定期统计文档数量和质量：
- 文档总数
- 各分类文档数
- 文档更新频率
- 文档访问热度

## 🤝 协作规范

### 文档作者责任
- 文档内容准确性
- 及时更新索引
- 回复文档相关问题

### 文档审核
- 重要文档需要审核
- 发现错误及时修正
- 定期清理过时文档

## 📞 问题反馈

发现文档问题，请：
1. 在对应文档中添加注释
2. 提交 Issue 说明问题
3. 直接修正并提交 PR
